# نوین‌شاپ — فروشگاه نمونه HTML/CSS/JavaScript

## اجرا در ویندوز
1. فایل ZIP را استخراج کن.
2. پوشه `novin-shop-announcements` را در VS Code باز کن.
3. ترمینال را در همان پوشه باز کن و اجرا کن:
   ```bash
   npm install
   npm start
   ```
4. مرورگر را روی `http://localhost:3000` باز کن. اجرای مستقیم `index.html` ممکن است باعث از کار افتادن API هوش مصنوعی و ذخیره اطلاعیه‌های سمت سرور شود.
5. برای ورود به پنل، دکمه «پنل مدیریت» را بزن؛ پنل در این نسخه دمو احراز هویت مدیر ندارد.

## امکانات
- ۳۰ محصول نمونه در دسته‌بندی‌های مختلف
- جست‌وجو، مرتب‌سازی و فیلتر موجودی
- سبد خرید با افزودن، حذف و تغییر تعداد
- ذخیره داده‌های فروشگاه در یک snapshot محلی مرورگر، با سازگاری و مهاجرت از کلیدهای قدیمی
- کدهای تخفیف نمونه NOVIN10 و WELCOME5
- ثبت سفارش و شبیه‌سازی پرداخت موفق/ناموفق
- پنل مدیر: داشبورد، CRUD محصولات، سفارش‌ها و وضعیت‌ها، مشتریان، گفت‌وگو، تخفیف‌ها، گزارش‌ها و خروجی CSV
- چت نمایشی مشتری/مدیر
- طراحی واکنش‌گرا برای موبایل و دسکتاپ

## ذخیره‌سازی، پشتیبان‌گیری و بازیابی

- داده‌های مرورگر در یک snapshot نسخه ۴ ذخیره می‌شوند؛ در صورت وجود داده‌های نسخه‌های قبلی، هنگام شروع خوانده شده و پس از ذخیره موفق به ساختار جدید منتقل می‌شوند.
- ذخیره‌سازی شامل محصولات، سبد خرید، سفارش‌ها، مشتریان، پیام‌های پشتیبانی، کدهای تخفیف، کیف پول، نشست کاربر و کد تخفیف اعمال‌شده است.
- در پنل مدیریت، بخش «نمای کلی» دکمه‌های «دانلود فایل پشتیبان کامل» و «بازیابی از فایل پشتیبان» دارد. بازیابی، داده‌های مرورگر فعلی را جایگزین می‌کند.
- فایل پشتیبان شامل داده‌های مشتریان و سفارش‌هاست؛ آن را در فضای خصوصی نگه دار و برای انتقال بین مرورگرها/دستگاه‌ها از آن استفاده کن.
- این پروژه هنوز پایگاه داده مشترک برای محصولات و سفارش‌ها ندارد؛ اطلاعات فروشگاه فقط در همان مرورگر ذخیره می‌شود. اطلاعیه‌های همگانی جداگانه در فایل JSON سرور نگهداری می‌شوند.
- رمز عبور در مرورگر با PBKDF2 و salt تصادفی هش می‌شود، اما چون احراز هویت سمت سرور و پنل مدیر محافظت‌شده وجود ندارد، این نسخه برای انتشار عمومی مناسب نیست.

## محدودیت‌های مهم
- همه قیمت‌ها و محصولات نمونه‌اند و برای قیمت روز بازار تأیید نشده‌اند.
- پرداخت کاملاً شبیه‌سازی است؛ هیچ پولی دریافت نمی‌شود و اطلاعات کارت بانکی نباید وارد شود.
- محصولات، سبد خرید، سفارش‌ها، مشتریان، پیام‌ها، تخفیف‌ها، کیف پول و نشست کاربر در همان مرورگر ذخیره می‌شوند؛ به دستگاه یا مرورگر دیگر منتقل نمی‌شوند مگر از پشتیبان‌گیری استفاده کنی.
- چت بین مرورگرها یا کاربران مختلف آنلاین نیست؛ برای آن سرور و WebSocket لازم است.
- پنل مدیر احراز هویت و سطح دسترسی امن ندارد. برای انتشار عمومی باید بک‌اند، دیتابیس، احراز هویت امن، اعتبارسنجی سمت سرور و درگاه پرداخت معتبر پیاده‌سازی شود.
- تصاویر محصولات با ایموجی نمایش داده شده‌اند تا پروژه بدون فایل تصویر اضافه اجرا شود. فونت آنلاین در صورت اتصال اینترنت بارگذاری می‌شود.

## امکانات افزوده‌شده در نسخه ارتقایافته
- تنظیم تاریخ تحویل، بازه زمانی، شرکت ارسال و کد رهگیری برای هر سفارش از جزئیات سفارش در پنل مدیر.
- نمایش زمان تحویل و اطلاعات رهگیری از طریق دستیار گفت‌وگو؛ مشتری شماره سفارش را در چت می‌فرستد.
- دستیار پاسخ‌گوی آزمایشی برای پرسش‌های رایج درباره محصولات، قیمت، تخفیف، ارسال و وضعیت سفارش.
- خروجی CSV سفارش‌ها شامل ستون‌های تاریخ تحویل، بازه زمانی، شرکت ارسال و کد رهگیری.

## یادآوری فنی
دستیار فعلی مبتنی بر قواعد ساده JavaScript است، نه مدل هوش مصنوعی آنلاین. برای اتصال به هوش مصنوعی واقعی باید یک API از طریق بک‌اند امن استفاده شود و کلید API هرگز در `app.js` سمت مرورگر قرار نگیرد. درگاه پرداخت همچنان آزمایشی است؛ اتصال به درگاه واقعی به حساب پذیرندگی و بک‌اند نیاز دارد.


## امکانات جدید نسخه توسعه‌یافته
- صفحه ثبت‌نام و ورود آزمایشی مشتری با شماره موبایل و رمز عبور، به‌همراه خروج از حساب.
- داشبورد مشتری برای مشاهده سفارش‌های خودش، وضعیت سفارش و زمان تحویل تعیین‌شده توسط مدیر.
- کیف پول آزمایشی با امکان شارژ نمایشی، نمایش تراکنش‌ها و پرداخت سفارش از موجودی کیف پول.
- شماره سفارش و شماره پیگیری پرداخت آزمایشی برای سفارش‌های پرداخت‌شده.
- گزارش فعالیت در پنل مدیریت برای رویدادهای ثبت‌نام، ورود، خروج و شارژ کیف پول؛ خروجی CSV نیز دارد.
- پنل مدیریت کیف پول‌ها و موجودی هر مشتری.

## محدودیت‌های امنیتی این نسخه
- حساب‌ها و رویدادها در مرورگر ذخیره می‌شوند. رمز عبور به‌صورت هش PBKDF2 با salt تصادفی ذخیره می‌شود و داده‌های قدیمی هنگام ورود موفق مهاجرت می‌کنند؛ بااین‌حال احراز هویت همچنان سمت مرورگر است و برای سایت عمومی امن محسوب نمی‌شود.
- ورود و خروج ثبت‌شده فقط رویدادهای همین مرورگر هستند، نه گزارش تمام دستگاه‌ها و کاربران اینترنت.
- ورود مدیر هنوز احراز هویت واقعی ندارد. قبل از انتشار عمومی باید بک‌اند، پایگاه داده، رمزنگاری امن رمز عبور، نشست‌های امن و نقش‌های دسترسی پیاده‌سازی شود.
- شارژ کیف پول و پرداخت کیف پول کاملاً نمایشی است. شماره پیگیری پرداخت با پیشوند DEMO ساخته می‌شود و سند بانکی نیست.
- برای اتصال به درگاه واقعی باید درگاه مورد تأیید، سرور و بررسی نتیجه تراکنش از سمت سرور راه‌اندازی شود؛ هیچ‌وقت کلید محرمانه در کد مرورگر قرار نگیرد.

## اتصال دستیار به هوش مصنوعی واقعی (Node.js + OpenAI API)

> برای این بخش باید کلید API خودت را داشته باشی. اشتراک ChatGPT به‌تنهایی لزوماً شامل اعتبار API نیست و مصرف API ممکن است هزینه جداگانه داشته باشد.

1. Node.js نسخه LTS را نصب کن.
2. این پوشه را در VS Code باز کن و در ترمینال اجرا کن: `npm install`
3. فایل `.env.example` را کپی کن و نام کپی را `.env` بگذار.
4. فایل `.env` را باز کن و مقدار `OPENAI_API_KEY` را با کلید API خودت جایگزین کن. کلید را در `app.js` یا هیچ کد سمت مرورگر قرار نده و فایل `.env` را برای کسی نفرست.
5. اجرا کن: `npm start`
6. در مرورگر آدرس `http://localhost:3000` را باز کن. برای چت هوشمند، سایت را از Live Server اجرا نکن؛ باید از همین آدرس سرور باز شود.

سرور از OpenAI Responses API استفاده می‌کند و فهرست محصولات فعلی را برای کمک در پیشنهاد خرید می‌فرستد. در صورت تنظیم نبودن کلید یا اجرا از Live Server، چت به پاسخ‌گوی محلی ساده برمی‌گردد. این نسخه هنوز دسترسی امن به سفارش‌ها و حساب مشتری را به مدل نمی‌دهد و نباید اطلاعات حساس مشتری را به مدل فرستاد. قبل از انتشار عمومی، احراز هویت مدیر، محدودسازی نرخ در چند نمونه سرور، حفاظت از داده‌ها و سیاست حریم خصوصی را کامل کن.


## پرداخت آزمایشی داخلی

در این نسخه، اتصال زرین‌پال حذف شده و تسویه‌حساب فقط از درگاه آزمایشی داخلی استفاده می‌کند. نیازی به شناسه پذیرنده، حساب زرین‌پال یا متغیرهای `ZARINPAL_*` نیست.

1. در پوشه پروژه ترمینال باز کن و `npm install` را اجرا کن.
2. سپس `npm start` را اجرا کن.
3. سایت را از `http://localhost:3000` باز کن. اگر پیام `EADDRINUSE` دیدی، یعنی پورت 3000 قبلاً توسط یک سرور دیگر اشغال شده است؛ سرور قبلی را متوقف کن یا از ترمینال همان سرور `Ctrl+C` بزن.
4. یک کالا به سبد اضافه کن و به تسویه‌حساب برو. گزینه «درگاه پرداخت آزمایشی» را انتخاب کن. کارت تستی را وارد کن، کد یک‌بارمصرف نمایشی را که روی همان صفحه نشان داده می‌شود تأیید کن؛ دکمه شبیه‌سازی ناموفق حذف شده است.

این پرداخت صرفاً نمایشی است و هیچ مبلغی دریافت نمی‌کند. اطلاعات کارت بانکی واقعی وارد نکن.

## اطلاعیه‌های همگانی در پنل مدیریت
در پنل مدیریت، بخش «اطلاعیه‌های همگانی» را باز کن و عنوان، متن، نوع پیام و تاریخ انقضا را وارد کن؛ سپس «انتشار اطلاعیه» را بزن. اطلاعیه فعال در بالای صفحه فروشگاه نمایش داده می‌شود. می‌توانی آن را غیرفعال یا حذف کنی. اطلاعیه‌های همگانی در فایل `data/announcements.json` روی سرور ذخیره می‌شوند و کاربران متصل به همان سرور آن‌ها را می‌بینند؛ برای استقرار چندسروری باید از پایگاه داده مشترک استفاده شود. این بخش پیامک SMS ارسال نمی‌کند.

طبق درخواست، مدیریت اطلاعیه‌ها رمز ندارد و نیازی به تنظیم `ANNOUNCEMENT_ADMIN_TOKEN` نیست. **هشدار:** اگر سایت را عمومی منتشر کنی، هر فردی که به API دسترسی داشته باشد می‌تواند اطلاعیه بسازد، تغییر دهد یا حذف کند. چون ورود مدیر هم در این نسخه احراز هویت واقعی ندارد، این حالت فقط برای نمونه/محیط مورداعتماد مناسب است.


## صفحه پرداخت آزمایشی و اطلاعیه‌های همگانی
- پرداخت از یک صفحه مستقل با ظاهر درگاه تستی در `payment.html` انجام می‌شود و سپس به فروشگاه برمی‌گردد. این صفحه به بانک یا زرین‌پال وصل نیست و اطلاعات کارت را ذخیره یا ارسال نمی‌کند. فقط اطلاعات تستی نمایش‌داده‌شده در صفحه را وارد کن.
- برای انتشار اطلاعیه برای تمام بازدیدکنندگان، پروژه باید با Node اجرا شود و همه کاربران از همان سرور/دامنه بازدید کنند؛ باز کردن مستقیم `index.html` با `file://` برای اطلاعیه‌های مشترک کار نمی‌کند.
- اطلاعیه‌ها در `data/announcements.json` روی سرور ذخیره می‌شوند و صفحه فروشگاه آن‌ها را هر ۱۵ ثانیه دوباره بررسی می‌کند.
- طبق درخواست، بخش اطلاعیه‌ها رمز ندارد. هر فردی که به API دسترسی داشته باشد می‌تواند اطلاعیه ایجاد، غیرفعال یا حذف کند؛ فقط در محیط آزمایشی/مورداعتماد استفاده شود.
- اجرا: `npm install` سپس `npm start` و بازکردن `http://localhost:3000`.


## تغییرات نسخه فعلی
- فوتر بازطراحی شده و شامل دسترسی سریع، پشتیبانی، پیگیری پرداخت آزمایشی و فرم عضویت نمایشی است.
- شارژ کیف پول از صفحه پرداخت آزمایشی عبور می‌کند و قبل از ثبت شارژ، کد یک‌بارمصرف نمایشی تأیید می‌شود. در این نسخه کد OTP فقط برای تست در همان صفحه نشان داده می‌شود و پیامک واقعی ارسال نمی‌شود.
- دکمه «شبیه‌سازی پرداخت ناموفق» حذف شده است.
- ربات پشتیبانی کد نمونه `DEMO-2671678370` را به‌عنوان پرداخت موفق آزمایشی توضیح می‌دهد؛ این کد تراکنش واقعی نیست.
- پنل مدیر مبلغ، وضعیت و شماره پیگیری تراکنش‌های کیف پول را نشان می‌دهد. شماره کامل کارت، CVV و تاریخ انقضای کارت ذخیره نمی‌شوند و از مدیر نیز پنهان می‌مانند. برای درگاه واقعی، باید از ارائه‌دهنده پرداخت معتبر استفاده شود و جزئیات کارت مستقیماً در صفحه امن همان ارائه‌دهنده وارد شود.

## امکانات افزوده‌شده در نسخه تکمیلی

- مدیریت محصول پیشرفته: SKU، بارکد، تأمین‌کننده، قیمت خرید، حد هشدار موجودی، عنوان سئو، برچسب‌های جست‌وجو، یادداشت داخلی، ویژه‌کردن، انتشار/پیش‌نویس، تکثیر محصول، اصلاح موجودی، هشدار موجودی و تغییر گروهی قیمت.
- پروفایل پنج‌بخشی: اطلاعات شخصی، نشانی‌ها، تاریخچه سفارش‌ها، علاقه‌مندی‌ها، کیف پول و پشتیبانی.
- سبد خرید: ذخیره کالا برای بعد، خالی‌کردن سبد، کد تخفیف و انتخاب شرکت ارسال.
- پنل «شرکت پست و ارسال»: مدیریت شرکت‌های نمونه، هزینه و زمان تقریبی؛ ثبت کد رهگیری در جزئیات سفارش.
- سفارش‌ها: جست‌وجو و فیلتر وضعیت، چاپ فاکتور، تغییر سریع مرحله، و نمایش اطلاعات گیرنده در بخش ارسال.
- صفحه مستقل `راهنمایی-خرید-شما.html` (همچنین نسخه سازگار `purchase-guide.html`) با راهنمای خرید، نشانی، پرداخت و رهگیری.
- اطلاعیه‌ها: صف نوشتن برای جلوگیری از تداخل هم‌زمان، اعتبارسنجی و مهاجرت اطلاعیه‌های محلی قدیمی در صورت خالی‌بودن ذخیره سرور.

**محدودیت مهم:** داده‌های محصولات، سفارش‌ها، پروفایل، سبد و کیف پول هنوز در localStorage همان مرورگر نگهداری می‌شوند؛ فقط اطلاعیه‌ها روی سرور ذخیره می‌شوند. شرکت‌های ارسال و پرداخت‌ها نمایشی‌اند و به سرویس واقعی وصل نیستند. API مدیریت اطلاعیه‌ها نیز برای دمو بدون رمز باقی مانده است؛ قبل از انتشار عمومی حتماً احراز هویت و کنترل دسترسی سمت سرور اضافه کنید.


## قابلیت‌های ورود و حساب کاربری (نسخه آزمایشی جدید)
- هدر و نوار دسته‌بندی فروشگاه هنگام ورود به پنل مدیریت پنهان می‌شوند و پنل مدیریت ظاهر مستقل خود را دارد.
- فرم ورود و ثبت‌نام بازطراحی شده و کد یک‌بارمصرف ۶ رقمی در جریان نمایشی تولید می‌شود؛ کد روی صفحه نمایش داده می‌شود و پیامک واقعی ارسال نمی‌شود.
- بازیابی رمز عبور با کد آزمایشی و تعیین رمز جدید اضافه شده است.
- رمز عبور و کد یک‌بارمصرف در گزارش مدیر نمایش داده نمی‌شوند. گزارش فعالیت فقط رویدادهایی مانند ثبت‌نام، ورود، خروج و بازیابی رمز را ثبت می‌کند.
- مشتری می‌تواند تصویر پروفایل انتخاب کند؛ تصویر در مرورگر تغییر اندازه داده و در همان مرورگر ذخیره می‌شود.
- مشتری واردشده می‌تواند زیر هر محصول امتیاز و نظر ثبت کند؛ هر حساب در این نسخه محلی برای هر محصول یک نظر ثبت می‌کند. نظرها و تصاویر پروفایل در فایل پشتیبان نسخه جدید نیز قرار می‌گیرند.
- دکمه‌های سریع پشتیبانی برای رهگیری سفارش، ارسال، گارانتی و پرداخت افزوده شده‌اند. صفحه «مدیران نوین‌شاپ» نقش‌های نمونه تیم را معرفی می‌کند؛ آواتارهای آن نمونه‌اند و اطلاعات تماس ساختگی ارائه نمی‌شود.

## هشدار مهم
کد OTP فقط روی صفحه نمایش داده می‌شود و امنیت واقعی پیامک را فراهم نمی‌کند. احراز هویت و بازیابی رمز در این پروژه سمت مرورگر هستند و پنل مدیریت نیز احراز هویت واقعی ندارد؛ بنابراین پروژه را بدون پیاده‌سازی بک‌اند امن و پایگاه داده واقعی برای استفاده عمومی منتشر نکن. نمایش رمز کاربران در پنل مدیریت عمداً پیاده‌سازی نشده است؛ رمز عبور و OTP نباید در گزارش‌ها یا پنل مدیر افشا شوند.


## رفع اشکال نسخه (۲۳ اکتبر ۲۰۲۶)

- تابع جست‌وجوی محصول بر اساس شناسه اضافه شد؛ این تابع به‌دلیل نبودن در نسخه قبلی باعث خطای JavaScript در محاسبه جمع سبد خرید و عملیات ویرایش/حذف/تکثیر محصول می‌شد.
- شناسه‌های عددی و متنی HTML dataset به‌صورت یکسان تطبیق داده می‌شوند.
- جست‌وجوی محصولات در پنل مدیریت در صورت نبودن API انتخاب متن، خطای ثانویه ایجاد نمی‌کند.
- خطای یک عملیات مدیریتی دیگر نباید بدون پیام به کاربر از بین برود؛ پیام خطا در رابط نمایش داده می‌شود و جزئیات برای بررسی در کنسول ثبت می‌شود.

### اگر دکمه‌ها هنوز واکنش نشان نمی‌دهند
1. پروژه را از طریق `npm install` و سپس `npm start` اجرا کن و آدرس `http://localhost:3000` را باز کن.
2. صفحه را با `Ctrl + F5` تازه‌سازی کن.
3. اگر از نسخه قبلی اطلاعات ذخیره‌شده داری، قبل از پاک‌کردن داده‌های مرورگر از پنل مدیریت فایل پشتیبان بگیر.
4. اگر خطایی در Console مرورگر می‌بینی، متن کامل آن را برای عیب‌یابی بفرست.

این پروژه هنوز نمونه آزمایشی است؛ داده‌های اصلی فروشگاه در مرورگر ذخیره می‌شوند و احراز هویت/پرداخت واقعی در آن پیاده‌سازی نشده است.


## به‌روزرسانی رابط کاربری (۲۳ اکتبر ۲۰۲۶)
- پنل مدیریت با نوار کناری خواناتر، حالت فعال مشخص، جداول قابل پیمایش و سازگاری بهتر با موبایل بهبود یافت.
- فرم محصول اکنون از آپلود تصویر PNG/JPEG/WebP یا واردکردن نشانی تصویر پشتیبانی می‌کند؛ فایل‌ها در مرورگر فشرده می‌شوند و در همان دستگاه ذخیره می‌شوند. محدودیت فضای مرورگر ممکن است برای تصاویر زیاد اثر بگذارد.
- ۲۰ محصول آزمایشی جدید با تصاویر وب اضافه شد؛ اتصال اینترنت برای دریافت تصاویر بیرونی لازم است.
- صفحه اصلی اسلایدر سه‌مرحله‌ای با کنترل دستی و چرخش خودکار دارد.
- بخش مشتریان گزینه‌های مدیریت اطلاعات، مشاهده سفارش‌ها، اصلاح کیف پول آزمایشی و ورود نمایشی به حساب را دارد. ورود نمایشی فقط برای آزمایش است و با دکمه خروج از حالت نمایشی می‌توان از آن خارج شد.
- صفحات مستقل `bank-mellat-demo.html`، `bank-melli-demo.html` و `zarinpal-demo.html` اضافه شدند. این صفحات کاملاً ساختگی‌اند، به بانک متصل نیستند و اطلاعات واقعی کارت یا CVV نمی‌گیرند.

### نکته مهم
این پروژه همچنان نسخه نمایشی است. داده‌های حساب، محصولات، سفارش و کیف پول عمدتاً در مرورگر ذخیره می‌شوند و نباید برای مشتریان واقعی یا پرداخت واقعی استفاده شوند. تصاویر ۲۰ محصول جدید از نشانی‌های بیرونی بارگذاری می‌شوند.

## اصلاحات نسخه ۲۳ اکتبر ۲۰۲۶ — حساب‌ها، نظرات و درگاه‌های HTML

- علاقه‌مندی‌ها اکنون با شناسه حساب (شماره موبایل نرمال‌شده) جدا ذخیره می‌شوند؛ حساب مهمان نیز فهرست مستقل دارد. فهرست قدیمی فقط برای حساب فعال زمان مهاجرت حفظ می‌شود تا بین حساب‌های جدید نشت نکند.
- فهرست مدیران مشتریان را از حساب‌های ثبت‌نام‌شده و مشتریان سفارش‌داده‌شده می‌سازد و تصویر پروفایل ذخیره‌شده را نشان می‌دهد.
- پنل «نظرات مشتریان» برای مرور نظرات، دیدن تصویر پروفایل/امتیاز و حذف نظر اضافه شده است؛ تصویر پروفایل نویسنده در جزئیات محصول نیز نمایش داده می‌شود.
- صفحه انتخاب پرداخت، سه سند HTML مستقل را به‌صورت کارت قابل انتخاب نمایش می‌دهد: `bank-mellat-demo.html`، `bank-melli-demo.html` و `zarinpal-demo.html`.
- در هر صفحه پرداخت، شماره کارت/تاریخ/CVV فقط مقادیر نمایشی نامعتبر و متفاوت برای هر مشتری هستند. هیچ فرم شماره کارت واقعی، CVV واقعی یا رمز بانکی وجود ندارد و هیچ داده پرداخت واقعی ذخیره نمی‌شود.
- لینک «معرفی مدیران و راه‌های ارتباطی» در فوتر عمومی نیز قرار گرفته است تا مشتریان به سند HTML دسترسی داشته باشند.
- دسته‌بندی‌ها از زیر هدر به کنار بخش محصولات منتقل شده‌اند و ظاهر هدر، دسته‌بندی‌ها و فهرست نظرات بهبود یافته است.
- لینک بازیابی رمز عبور در فرم ورود/ثبت‌نام قابل مشاهده است؛ در نسخه آزمایشی کد بازیابی روی صفحه نمایش داده می‌شود و پیامک واقعی ارسال نمی‌شود.
