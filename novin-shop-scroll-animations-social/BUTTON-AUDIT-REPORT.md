# گزارش بررسی دکمه‌ها و تعاملات نوین‌شاپ

## اصلاح قطعی این نسخه
- دکمه × بستن اطلاعیه‌های نوین‌شاپ به شنونده‌ی کلیک سراسری متصل شد.
- پس از بستن اطلاعیه، شناسه‌ی آن در `dismissed_announcements` ذخیره می‌شود، رابط دوباره رندر می‌شود و اطلاعیه تا پاک‌کردن داده‌های مربوطه دوباره نمایش داده نمی‌شود.
- دکمه‌های اقدام داخل فرم‌های خبرنامه و گفت‌وگوی پشتیبانی نوع صریح `submit` گرفتند؛ دکمه‌ی رفتن به محصولات نیز `type="button"` شد تا ارسال ناخواسته‌ی فرم ایجاد نکند.

## بررسی‌های خودکار انجام‌شده
- بررسی نحوی تمام ۸ فایل JavaScript پروژه با `node --check`: موفق.
- بررسی ارجاع‌های محلی script و stylesheet در صفحات اصلی HTML: هیچ فایل ارجاع‌شده‌ی مفقودی پیدا نشد.
- بررسی شناسه‌های تکراری در صفحات اصلی HTML: موردی پیدا نشد.
- بررسی ساختار آرشیو ZIP: سالم.

## محدودیت آزمون
این محیط مرورگر واقعی و وابستگی‌های نصب‌شده‌ی پروژه را در اختیار نداشت؛ بنابراین کلیک واقعی روی تمام ۳۱۵ دکمه‌ی HTML و کنترل‌های ساخته‌شده به‌صورت پویا، ورود چندحسابی، پرداخت و مسیرهای وابسته به API به‌صورت انتها‌به‌انتها اجرا نشده‌اند. این گزارش ادعای «تضمین بدون باگ بودن همه‌ی دکمه‌ها» نمی‌کند. برای آزمون کامل باید پروژه روی سیستم مقصد با سرور و مرورگر اجرا و مسیرهای کاربری واقعی بررسی شوند.
